## 2. Objetivo
Que el equipo técnico **se entere solo** cuando una tarea programada deja de funcionar y pueda **consultar su estado**: (1) cada tarea acumula sus **fallos consecutivos**; al **tercer fallo seguido** se envía **una alerta por correo** a la lista `alertas_tecnicas` con la plantilla nueva `alerta_tarea_fallida`; (2) una tarea que **no corre durante el doble de su intervalo** genera una **alerta de retraso**; (3) un servicio de la BLL expone el **estado de cada tarea** (última ejecución, resultado, próxima ejecución, fallos, retraso) y el **historial paginado**, listo para que lo muestre el panel cuando exista autorización (HU-019/HU-020); (4) toda alerta queda además en el **log estructurado**. No hay controlador, API ni vista en esta HU (SUP-7).

### 4.4 Política y servicios de la BLL
**`src/Nilogistic.BLL/Tareas/PoliticaAlertasTareas.cs`** (estática, pura): `const int UmbralFallosConsecutivos = 3`, `const int FactorRetraso = 2`, y `static bool EstaEnRetraso(string programacion, bool activa, DateTime? ultimaUtc, DateTime? proximaUtc, DateTime ahoraUtc)`: `false` si no está activa, si la programación no tiene intervalo válido (`ProgramacionTarea.TryObtenerIntervalo`) o si `ultimaUtc` es `null` (una tarea que aún no corre no se evalúa; SUP-4); `false` si `proximaUtc` es posterior a `ahoraUtc` (hay reserva o espera vigente, la tarea no está vencida); en otro caso `ahoraUtc - ultimaUtc > FactorRetraso * intervalo`.

**`IServicioAlertasTareas` / `ServicioAlertasTareas`** (BLL; depende de `IRepositorioTareas`, `IServicioDestinatariosAviso`, `IServicioPlantillasCorreo`, `IRelojUtc`, `IOptions` de la URL base del sitio igual que `ServicioDestinatariosAviso`, `ILogger`):
- `Task RegistrarDesenlaceAsync(string tarea, bool exitoso, string? error, CancellationToken)`: llama al DAL; si `!exitoso` y `FallosConsecutivos >= Umbral` y `ReclamarAlertaFallosAsync` devuelve `true` → `EnviarAlertaAsync(tarea, "fallos", motivo: "N fallos consecutivos", detalle: error)`.
- `Task<int> EvaluarRetrasosAsync(CancellationToken)`: `ListarEstadoAsync` → para cada tarea con `PoliticaAlertasTareas.EstaEnRetraso(...)` y `AlertaRetrasoUtc is null` → `ReclamarAlertaRetrasoAsync`; si `true` → `EnviarAlertaAsync(tarea, "retraso", motivo: "Sin ejecutarse desde hace H h M min (intervalo I s)", detalle: último resultado/error de esa tarea o «—»)`. Devuelve cuántas alertas procesó.
- `EnviarAlertaAsync` (privado): (1) escribe **siempre** un `LogError` estructurado con propiedades `{Tarea}`, `{Tipo}`, `{Motivo}`, `{Detalle}` (plantilla de mensaje fija, sin interpolar); (2) obtiene `ObtenerActivosAsync(ListasAviso.AlertasTecnicas)`; **lista vacía → `LogError` adicional «sin destinatarios» y termina sin lanzar** (SUP-3; el aviso se considera atendido); (3) encola la plantilla `alerta_tarea_fallida` **un correo por destinatario** con clave `alerta_tarea:{tipo}:{tarea}:{yyyyMMddHH}:{hash16 del correo}` (mismo esquema que `prueba_avisos`; el hash no expone el correo). Variables: `url_base`, `tarea`, `motivo`, `detalle`, `fecha_hora` (hora de Nicaragua, mismo formateador que `prueba_avisos`; reutiliza o extrae el helper, sin duplicar lógica). `detalle` contiene **solo** el nombre del tipo de excepción o el código acotado ya guardado (SUP-8 de HU-034), nunca mensajes ni datos sensibles.
- **Ningún fallo de la alerta puede romper al ejecutor:** cualquier excepción al enviar (salvo `OperationCanceledException` con cancelación solicitada, que se relanza) se captura y se registra con `LogError`.

**`IServicioEstadoTareas` / `ServicioEstadoTareas`** (solo lectura; sin autorización: SUP-7):
- `Task<IReadOnlyList<EstadoTareaResponse>> ObtenerEstadoAsync(CancellationToken)`.
- `Task<IReadOnlyList<EjecucionTareaResponse>> ObtenerEjecucionesAsync(string tarea, int pagina, int tamano, CancellationToken)`: `pagina` mínimo 1, `tamano` acotado a 1..100 (por defecto 20); tarea vacía → lista vacía.
- Estado derivado (`enum SaludTarea { Inactiva, SinEjecutar, Correcta, ConFallos, EnRetraso }`), en este orden de prioridad: `Inactiva` si no está activa; `EnRetraso` si `PoliticaAlertasTareas.EstaEnRetraso`; `ConFallos` si `FallosConsecutivos > 0`; `SinEjecutar` si nunca corrió; `Correcta` en otro caso.

**`Tareas/TareaVigilarTareas.cs`**: `ITareaProgramada` con `Nombre => "vigilar_tareas"` que llama a `IServicioAlertasTareas.EvaluarRetrasosAsync`. Idempotente (el reclamo atómico evita duplicar alertas).

**`ServicioEjecutorTareas`** (cambio mínimo, **sin alterar** reintentos, timeout ni reservas): el ciclo de una tarea devuelve su desenlace final (`Exitosa`; o `Fallida`/`Cancelada` por timeout y el nombre del error). Tras cerrar el último intento, **antes** de `ProgramarAsync`, llama a `IServicioAlertasTareas.RegistrarDesenlaceAsync(nombre, exitoso, error)`. Cuentan como fallo del ciclo: excepción tras agotar reintentos, timeout, `SinManejador` y `ProgramacionInvalida`. **No** se registra el apagado del host (`ApagadoDelServicio`). Los intentos intermedios de reintento **no** suman fallos (un ciclo = un desenlace).

   migración `.001500` la siembra. Las aserciones existentes no se modificaron.

   nuevas de alertas insertan con `on conflict (nombre) do update` para fijar el estado inicial en
   lugar de asumir una tabla vacía.
