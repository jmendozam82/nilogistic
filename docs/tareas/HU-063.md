## 2. Objetivo
Que Administración pueda definir **quién envía** y **quién recibe** los avisos del sistema sin desplegar código: (1) un **remitente por flujo** de correo (transaccional, contacto, marketing), con nombre y dirección de un **dominio verificado**; (2) **cuatro listas de destinatarios** (nuevas solicitudes de alta, contacto, alertas técnicas y continuidad) con sus mínimos; (3) un **correo de prueba** a cualquier dirección. Los cambios se auditan con valores antes y después. `ServicioCorreo` pasa a usar el remitente configurado (con respaldo en `appsettings`). **No hay pantalla, endpoint ni autorización en esta HU** (la superficie HTTP llega con HU-019/HU-020 y la pantalla de configuración con HU-062b).

### 4.1 Pase A — Migración SQL (`supabase/migrations/20261109001300_destinatarios_y_remitentes.sql`)
Timestamp mayor que el último (`20261109001200`). Una sola transacción; **idempotente** (la CI la aplica dos veces); mismo rol dueño que las anteriores. Ambas tablas llevan las columnas base (`id uuid primary key default gen_random_uuid()`, `activo boolean not null default true`, `creado_utc timestamptz not null default now()`, `actualizado_utc timestamptz not null default now()`, `creado_por uuid null`, `actualizado_por uuid null`, sin clave foránea a usuarios porque aún no existe `identidad.usuarios`).

1. **`app.destinatarios_aviso`**: `lista text not null check (lista in ('nuevas_solicitudes','contacto','alertas_tecnicas','continuidad'))`, `correo extensions.citext not null check (length(correo) <= 254 and correo ~ '^[^@\s,;<>"()\[\]\\]+@[^@\s,;<>"()\[\]\\]+\.[^@\s,;<>"()\[\]\\]+$')`, `es_buzon_compartido boolean not null default false`. Único `unique (lista, correo)` (citext: sin distinguir mayúsculas). Índice `ix_destinatarios_aviso_lista on (lista) where activo`.
2. **`app.remitentes_correo`** (tabla nueva, D-146): `flujo text not null unique check (flujo in ('transaccional','contacto','marketing'))`, `nombre text not null check (length(btrim(nombre)) between 1 and 100 and nombre !~ '[<>"\r\n]')`, `correo extensions.citext not null` (mismo `check` de formato y longitud).
3. **RLS de denegación por defecto** y políticas para `nilogistic_app` **por comando** (`select`, `insert`, `update`), cada una precedida de `drop policy if exists`. **Sin política de delete.**
4. **Privilegios:** `revoke insert, update, delete ... from nilogistic_app` y luego `grant select, insert, update` en ambas. **Sin `delete`** (soft delete con `activo`).
5. **Comentarios** `comment on table/column` en español (lista de valores permitidos, que los remitentes sobrescriben a `Correo:Remitentes` y que las listas son conjuntos de correos activos).
6. **Sin semilla** (SUP-2): las listas arrancan vacías y sin remitentes configurados; el respaldo es `appsettings`.

#### 4.3.a Comportamiento de `ServicioRemitentes.ActualizarAsync` (E2)
1. `Flujo` fuera de `FlujosCorreo.Todos` → `Invalido`. `Nombre` recortado de 1 a 100 caracteres, sin caracteres de control ni `<`, `>`, `"` → `Invalido`. `Correo` inválido según `ValidadorDireccionCorreo` → `Invalido`.
2. **Dominio verificado:** el dominio del correo (en minúsculas) debe ser **igual** a uno de `OpcionesCorreo.DominiosVerificados` (comparación exacta; un subdominio no se acepta por tener el dominio padre verificado). Si no → `DominioNoVerificado` con un mensaje que explica que el dominio debe verificarse antes en Resend (mensaje en ASCII, sin repetir la lista completa). No se escribe nada.
3. Lee la fila actual del flujo; `antes` = `{nombre, correo, origen}` (con `origen = "predeterminado"` y los valores de `appsettings` si no hay fila). Construye la entidad y el asiento y llama a `GuardarAsync` con `correoEsperado` = correo de la fila actual (nulo si no hay). `Conflicto` si el repositorio lo devuelve.
4. **Asiento:** `Tipo = "gestion"`, `Accion = "remitente_actualizado"`, `Entidad = "app.remitentes_correo"`, `EntidadId = <id>`, `Antes`/`Despues` como arriba, con usuario, rol, IP, user agent y correlación de `IContextoAuditoria`, `OcurrioUtc = reloj.AhoraUtc`.
5. `ObtenerEfectivoAsync` devuelve `Nombre <correo>` en el formato exacto `"{nombre} <{correo}>"`.

#### 4.3.b Comportamiento de `ServicioDestinatariosAviso`
- **`ObtenerActivosAsync`:** `lista` inválida → `ArgumentException` genérica; devuelve solo activos, ordenados por correo, sin consultar inactivos. Una lista vacía es válida (SUP-2).
- **`ActualizarListaAsync` (E1, E3, E5, E6)** — la lista se reemplaza completa; los mínimos se validan sobre el **resultado final**:
  1. `Lista` inválida → `Invalida`. Cada correo recortado y pasado a minúsculas debe ser válido (`ValidadorDireccionCorreo`); duplicados (sin distinguir mayúsculas) → `Invalida`; máximo **20** destinatarios por lista → `Invalida`.
  2. **Mínimos:** todas las listas exigen al menos 1 destinatario (E3: quitar al último de `alertas_tecnicas` se bloquea). La lista `contacto` exige **al menos 2** (E5) y **al menos uno con `EsBuzonCompartido = true`** (E6). Mensajes en ASCII que nombran la regla incumplida.
  3. Lee los activos actuales; si el conjunto deseado es igual (correos y marca) → `SinCambios` (sin escritura ni asiento).
  4. Construye el asiento y llama a `ReemplazarListaAsync` con los correos activos leídos como `activosEsperados`; `Conflicto` si el repositorio lo devuelve. Devuelve `Actualizada` con la lista resultante (E1).
  5. **Asiento:** `Tipo = "gestion"`, `Accion = "destinatarios_actualizados"`, `Entidad = "app.destinatarios_aviso"`, `EntidadId = <lista>`, `Antes = {"lista","destinatarios":[{"correo","es_buzon_compartido"}]}` y `Despues` igual con el conjunto final; actor y contexto de `IContextoAuditoria`.
- **`EnviarPruebaAsync` (E4):** `Lista` válida y `Correo` válido → `Invalida` si no. Encola con `IServicioPlantillasCorreo.EncolarAsync` la plantilla `prueba_avisos` (`url_base` = `OpcionesCorreo.UrlBaseSitio`, `lista` = nombre legible de la lista, `fecha_hora` en hora de Nicaragua) a esa dirección, con `ClaveIdempotencia = "prueba_avisos:{hash}:{yyyyMMddHH}"` donde `hash` son los primeros 16 caracteres hexadecimales del SHA-256 del correo en minúsculas y la hora es la actual en UTC: un envío de prueba por dirección y por hora (`YaEnviadaEstaHora` si el resultado es `Duplicado`). Cualquier rechazo del encolado → `Invalida`. Sin enviar a direcciones que no estén en la lista: **la prueba puede ir a una dirección nueva** (aún no guardada). Escribe un asiento `Tipo = "gestion"`, `Accion = "correo_prueba_solicitado"`, `Despues = {"lista","correo"}` solo cuando quedó `Encolada` (SUP-7).
- **Privacidad:** ni los correos ni la IP van a los logs; solo la lista y el estado.
- **Sin autorización, sin 2FA, sin HTTP** (SUP-5): la regla «Administrador (READ y UPDATE sobre Configuración)» se aplica con HU-019/HU-020.
