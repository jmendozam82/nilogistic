## 2. Objetivo
Garantizar y demostrar que **nadie** puede modificar ni borrar un registro de auditoría: ni el rol de la aplicación, ni el Administrador, ni un descuido de código. La inmutabilidad se aplica en tres niveles: privilegios (HU-008), un **trigger de defensa en profundidad** que rechaza `UPDATE` y `DELETE` incluso al propietario de la tabla, y la ausencia de cualquier endpoint o método de código que los intente. Una corrección se registra como un **asiento nuevo ligado al original**, que permanece sin cambios.

## 4. Alcance

### 4.1 Migración SQL de defensa en profundidad
Archivo `supabase/migrations/<timestamp>_auditoria_inmutable.sql` (el `<timestamp>` debe ser **mayor que el último de `supabase/migrations/`**, D-21; una transacción; idempotente):
- Función `auditoria.impedir_modificacion()` (`language plpgsql`, `security invoker`, `set search_path = pg_catalog, auditoria`) que ejecuta `raise exception 'La auditoria es inmutable: % no esta permitido', tg_op using errcode = '42501';` (`insufficient_privilege`, para que el código de error sea el mismo que el de un permiso denegado).
- Trigger `trg_registros_inmutable` `before update or delete on auditoria.registros for each row execute function auditoria.impedir_modificacion();` creado en la tabla **padre** (PostgreSQL 17 lo propaga a todas las particiones, existentes y futuras). Idempotente: `drop trigger if exists ... ; create trigger ...`.
- Comentario de tabla actualizado (en español) indicando que es inmutable.
- No se concede ni se revoca ningún privilegio (ya resueltos en HU-008). `TRUNCATE` queda cubierto por la ausencia de ese privilegio para `nilogistic_app`; no se crea trigger de `truncate`.
- Confirma que `scripts/ci/verificar_rls.sql` sigue en verde. Si el trigger lo rompe, **no relajes la guardia**: anótalo en "Dudas".

## 6. Prohibiciones (se revisan al pie de la letra)
- Ninguna capa se salta otra: Controller → BLL → DAL. Aquí no hay controllers.
- **Ningún** método, endpoint, SQL o prueba de producción que haga `UPDATE`, `DELETE` o `TRUNCATE` sobre `auditoria.registros`, ni que desactive el trigger (`alter table ... disable trigger`). Las pruebas **intentan** `UPDATE`/`DELETE` solo para comprobar que fallan.
- No cambiar `RegistroAuditoria` ni `ConfiguracionRegistroAuditoria` (si necesitas algo de ellos, anótalo en "Dudas").
