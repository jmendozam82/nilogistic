## 2. Objetivo
Entregar el servicio de correo transaccional: una cola persistida en `app.cola_correo`, un procesador en segundo plano (tarea `procesar_cola_correo` sobre el ejecutor de HU-034) y un adaptador de Resend, con reintentos de espera exponencial, idempotencia por clave, estados `EnCola`/`Enviado`/`Fallido`, y sin envío real en Desarrollo y Pruebas. Un fallo de envío nunca revierte la operación de negocio que lo originó. Esta HU **no trae plantillas** (HU-030), **ni webhooks** (HU-065), **ni pantallas**: otras HU encolan mensajes llamando a `IServicioCorreo`.

**`OpcionesCorreo`** (sección `Correo`; los setters acotan con `Math.Clamp`, como `OpcionesEjecutorTareas`): `bool ForzarBuzon = false`; `Remitentes` (`Transaccional = "Nilogistic <no-reply@nilogistic.com>"`, `Contacto = "Nilogistic <no-reply@nilogistic.com>"`, `Marketing = null`); `LoteMaximo = 20` (1..100); `ReservaSegundos = 600` (60..3600); `MaxReintentos = 3` (0..10); `EsperaBaseReintentoSegundos = 60` (1..3600); `FactorEspera = 4` (2..10); `PausaEntreEnviosMs = 600` (0..5000); `ConservarDias = 30` (1..365); `VaciarCuerposAlEnviar = true`.
**`OpcionesResend`** (sección `Resend`): `string? ApiKey` (secreto: **nunca** valor en archivos versionados), `string UrlBase = "https://api.resend.com"`, `int TimeoutSegundos = 15` (5..60).

**`ProveedorCorreoResend`** (constructor `(HttpClient http, OpcionesResend opciones)`):
- `POST {UrlBase}/emails`, JSON con `System.Text.Json`: `from`, `to` (arreglo de **un** elemento), `subject`, `html`, `text` y `reply_to` (solo si hay `ResponderA`). Cabeceras por solicitud: `Authorization: Bearer <ApiKey>`, `Idempotency-Key: <ClaveIdempotencia>` y `User-Agent: Nilogistic/1.0` (Resend rechaza solicitudes sin User-Agent). La ApiKey no se guarda en `DefaultRequestHeaders`, no se escribe en ningún mensaje de error y no se registra.
- Respuesta 2xx: leer `id` del JSON → `Enviado` con `IdProveedor`. Si el JSON no trae `id`, igual es `Enviado` con `IdProveedor = null`.
- Clasificación (SUP-3): HTTP 408, 409, 425, 429 y 5xx → `Transitorio` con código `Http<status>`; cualquier otro 4xx (incluidos 400, 401, 403, 422) → `Permanente` con `Http<status>`; `HttpRequestException` → `Transitorio` `ErrorDeRed`; timeout propio (`TaskCanceledException` sin cancelación del token) → `Transitorio` `TiempoAgotado`. **Nunca** se guarda el cuerpo de la respuesta (puede traer direcciones de correo).
- Si `cancelacion` está cancelado, relanzar `OperationCanceledException`.

**`GuardiaCorreo.Validar(string entorno, OpcionesCorreo correo, OpcionesResend resend)`** (SUP-1):
- Entornos `Staging` y `Production` envían por Resend, salvo `Correo:ForzarBuzon = true`. Cualquier otro entorno (`Development`, `Testing`, …) usa el buzón y **no** exige clave.
- En `Production`, `ForzarBuzon = true` es un error (correo apagado en silencio).
- Si va a usar Resend: `ApiKey` no vacía, `UrlBase` con esquema `https`, y `Remitentes.Transaccional` y `Remitentes.Contacto` válidos (`correo@dominio` o `Nombre <correo@dominio>`). Los mensajes de excepción **no** incluyen valores de configuración.
- Añadir `Testing` no se hace en `Entornos`; la regla "todo lo que no sea Staging ni Production usa buzón" no necesita la constante.

```csharp
public sealed record CorreoNuevo(Guid Id, string Tipo, string Plantilla, string VersionPlantilla,
    string Destinatario, string? ResponderA, string Asunto, string CuerpoHtml, string CuerpoTexto,
    string ClaveIdempotencia, DateTime CreadoUtc);

public sealed record CorreoReservado(Guid Id, string Tipo, string Destinatario, string? ResponderA,
    string Asunto, string CuerpoHtml, string CuerpoTexto, string ClaveIdempotencia, int Intentos);

Task<bool> EncolarAsync(CorreoNuevo correo, CancellationToken cancelacion = default);   // true = insertado; false = la clave ya existia (E4)
Task<IReadOnlyList<CorreoReservado>> ReservarLoteAsync(DateTime ahoraUtc, int maximo, int reservaSeg, CancellationToken cancelacion = default);
Task MarcarEnviadoAsync(Guid id, string? idProveedor, DateTime enviadoUtc, DateTime conservarHastaUtc, bool vaciarCuerpos, CancellationToken cancelacion = default);
Task RegistrarFalloAsync(Guid id, int intentos, DateTime? siguienteIntentoUtc, bool definitivo, string error, DateTime? conservarHastaUtc, CancellationToken cancelacion = default);
```
- `EncolarAsync`: `insert into app.cola_correo (...) values (...) on conflict (clave_idempotencia) do nothing` con `ExecuteSqlInterpolatedAsync`; devuelve `filasAfectadas == 1`. Estado inicial `EnCola`, `intentos = 0`, `siguiente_intento_utc = null`. **Usa el `DbContext` del ámbito, sin abrir transacción propia**: si la BLL del consumidor abre una, el encolado participa en ella (patrón outbox). Dentro de una transacción revertida no queda fila (prueba obligatoria).
- `ReservarLoteAsync`: una sola sentencia atómica con `Database.SqlQuery<CorreoReservado>(...).AsAsyncEnumerable()`, como en `RepositorioTareas`:
```sql
update app.cola_correo
   set siguiente_intento_utc = {ahora} + make_interval(secs => {reservaSeg}::double precision)
 where id in (select id from app.cola_correo
               where estado = 'EnCola' and (siguiente_intento_utc is null or siguiente_intento_utc <= {ahora})
               order by coalesce(siguiente_intento_utc, creado_utc), creado_utc
               limit {maximo}
               for update skip locked)
returning id as "Id", tipo as "Tipo", destinatario::text as "Destinatario", responder_a::text as "ResponderA",
          asunto as "Asunto", cuerpo_html as "CuerpoHtml", cuerpo_texto as "CuerpoTexto",
          clave_idempotencia as "ClaveIdempotencia", intentos as "Intentos"
```
  La nueva `siguiente_intento_utc` es una **reserva (lease)**: dos instancias no toman el mismo mensaje; si una muere, la reserva vence y otra lo retoma (el `Idempotency-Key` evita el doble envío si el mensaje ya había salido).
- `MarcarEnviadoAsync`: `estado = 'Enviado'`, `resend_id`, `enviado_utc`, `conservar_hasta_utc`, `intentos = intentos + 1`, `siguiente_intento_utc = null`, `error = null`; si `vaciarCuerpos`, `cuerpo_html = ''` y `cuerpo_texto = ''` (SUP-6).
- `RegistrarFalloAsync`: `intentos = {intentos}`, `error = {error}`; si `definitivo`: `estado = 'Fallido'`, `siguiente_intento_utc = null`, `conservar_hasta_utc = {conservarHastaUtc}`; si no: `estado = 'EnCola'`, `siguiente_intento_utc = {siguienteIntentoUtc}`.

**`EncolarAsync` — validación (sin FluentValidation: el paquete aún no está en `Directory.Packages.props`; no lo agregues).** Devuelve `Rechazado` con motivo (sin lanzar) si:
- `Tipo` no está en `transaccional|marketing|contacto`, o su remitente no está configurado (`marketing` hoy no lo está → motivo `RemitenteNoConfigurado`).
- `Destinatario` (y `ResponderA`, si viene) no cumple `^[^@\s,;<>"()\[\]\\]+@[^@\s,;<>"()\[\]\\]+\.[^@\s,;<>"()\[\]\\]+$`, supera 254 caracteres o contiene caracteres de control. **Un solo destinatario por mensaje.**
- `Plantilla` vacía o de más de 100 caracteres; `VersionPlantilla` vacía o de más de 20; `CuerpoHtml` o `CuerpoTexto` vacíos o de más de 200 000 caracteres.
- `ClaveIdempotencia` vacía, de más de 200 caracteres o fuera de `[A-Za-z0-9:_.-]`.

**Neutralización del asunto** (inyección de cabeceras; la reutiliza HU-043 E4): se reemplazan `\r`, `\n` y demás caracteres de control por un espacio, se colapsan los espacios y se recorta; si queda vacío o supera 200 caracteres → `Rechazado`.
Con la solicitud válida: `Id = Guid.NewGuid()`, `CreadoUtc = reloj.AhoraUtc`; `repositorio.EncolarAsync(...)` → `true` = `Encolado` con el `Id`; `false` = `Duplicado` (E4), sin segundo envío.

**`ProcesarColaAsync`:**
1. `ReservarLoteAsync(reloj.AhoraUtc, opciones.LoteMaximo, opciones.ReservaSegundos)`; si viene vacío, devolver 0.
2. Por cada mensaje, en serie (nunca en paralelo): resolver el remitente por `Tipo`; si falta → fallo definitivo con error `RemitenteNoConfigurado`. Si no, `proveedor.EnviarAsync(...)` dentro de `try/catch`: una excepción inesperada (que no sea cancelación) se trata como `Transitorio` con error = **nombre del tipo de la excepción**.
3. Resultado:
   - `Enviado` → `MarcarEnviadoAsync(id, idProveedor, ahora, ahora + ConservarDias, opciones.VaciarCuerposAlEnviar)`.
   - `Permanente` → `RegistrarFalloAsync(definitivo: true, intentos + 1, error = código, conservarHasta = ahora + ConservarDias)`.
   - `Transitorio` → sea `n = Intentos + 1`. Si `n <= MaxReintentos` (quedan reintentos): `RegistrarFalloAsync(definitivo: false, intentos: n, siguienteIntentoUtc: ahora + EsperaBase * FactorEspera^(n-1))` (con los valores por defecto: 60 s, 240 s, 960 s). Si no, fallo definitivo. Total: **1 envío inicial + 3 reintentos**.
4. Entre mensajes, `IEspera.EsperarAsync(PausaEntreEnviosMs)` (Resend limita a unas 2 solicitudes por segundo); no esperar tras el último.
5. Si el host cancela, detenerse y relanzar: los mensajes reservados vuelven a estar disponibles cuando venza su reserva.
6. Si registrar el resultado lanza, `LogError` y seguir con el siguiente: la reserva vence y el mensaje se retoma (el `Idempotency-Key` evita el doble envío).
7. Todos los `DateTime` salen de `IRelojUtc`. Logs estructurados con `CorreoId`, `Tipo`, `Intento`, `Resultado`, `Codigo` y `DuracionMs`. **Nunca** destinatario, asunto, cuerpo ni clave de API.

## 6. Prohibiciones (se revisan al pie de la letra)
- No llamar al DAL desde Controllers ni Vistas; ninguna capa se salta otra. Reintentos, clasificación, plazos y validación van en la BLL; el DAL solo ejecuta SQL. Solo `Nilogistic.DAL.Interfaces` es visible para la BLL.

- No agregar paquetes NuGet. Todo namespace empieza con `Nilogistic`.
- **Commits:** Conventional Commits, asunto ASCII (sin acentos ni eñes) de 72 caracteres o menos, ámbito en minúsculas (por ejemplo `feat(correo): ...`), por ruta, nunca `git add .`. Valida con `python3 scripts/ci/validar_conventional_commits.py --base develop`. Sin push.
