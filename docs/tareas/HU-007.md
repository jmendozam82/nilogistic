## 2. Objetivo
Entregar la entidad base y el repositorio genérico que implementan soft delete, de modo que ninguna entidad futura pueda borrarse: solo pasa de activo a inactivo. Las fechas se guardan siempre en UTC y las columnas base se llenan solas.

### 4.3 Contrato de `IRepositorioBase<T>` (`where T : EntidadBase`)
```csharp
Task<T?> ObtenerAsync(Guid id, bool incluirInactivos = false, CancellationToken cancelacion = default);
Task<ResultadoPaginado<T>> ListarAsync(int pagina = 1, int tamano = 20, bool incluirInactivos = false, CancellationToken cancelacion = default);
Task<T> AgregarAsync(T entidad, CancellationToken cancelacion = default);
Task<ResultadoEscritura> ActualizarAsync(T entidad, CancellationToken cancelacion = default);
Task<ResultadoEscritura> DesactivarAsync(Guid id, CancellationToken cancelacion = default);
Task<ResultadoEscritura> ReactivarAsync(Guid id, CancellationToken cancelacion = default);
```
Comportamiento exigido:
- **No existe ningún método de eliminación** (ni `Eliminar`, `Borrar`, `Delete`, `Remove`, `Quitar` ni equivalentes) en la interfaz ni en la clase, ni públicos ni protegidos.
- **No exponer** `IQueryable`, `DbSet` ni tipos de EF Core: la BLL no puede depender de EF Core.
- Por defecto se excluyen los inactivos; `incluirInactivos = true` los incluye (ignorando **solo** el filtro de soft delete si la versión de EF lo permite, ver SUP-3).
- `ListarAsync`: orden determinista por `FechaCreacionUtc` y luego `Id`; `pagina >= 1` y `1 <= tamano <= 100`, si no `ArgumentOutOfRangeException` (SUP-5); `Total` cuenta según `incluirInactivos`.
- `DesactivarAsync` / `ReactivarAsync`: buscan **sin filtro** de soft delete. `NoEncontrado` si el Id no existe; `SinCambios` si ya está en el estado pedido (no escribir nada); `Aplicado` si cambió `Activo`.
- `ActualizarAsync`: busca la existente sin filtro; si no existe, `NoEncontrado`. Copia los valores recibidos pero **conserva** los originales de `Id`, `Activo`, `FechaCreacionUtc` y `CreadoPor` (el estado solo cambia con Desactivar/Reactivar).
- `AgregarAsync` devuelve la entidad con `Id` y fechas ya asignados.

## 6. Prohibiciones (se revisan al pie de la letra)
- Ninguna capa se salta otra. El DAL no referencia BLL, DTO, API ni Aplicación; la Entity no referencia nada; la BLL no referencia EF Core.
- Prohibido `DELETE`, `ExecuteDelete`, `Remove`, `RemoveRange` y `EntityState.Deleted` en `src/`.
- Prohibido `DateTime.Now`, `DateTime.UtcNow` y `DateTimeOffset.Now` fuera de `RelojSistema`. Las fechas salen de `IRelojUtc`.
- Prohibido agregar paquetes NuGet. Usar solo los de `Directory.Packages.props`.
- Prohibido el nombre de cualquier otro proyecto en namespaces, comentarios o SQL; todo namespace empieza con `Nilogistic`.
- Prohibido silenciar advertencias o relajar las pruebas de arquitectura para que pasen.
- Estilo: nombres en español, comentarios XML `summary` cortos y solo donde aporten.

## 8. Seguridad, permisos, auditoría y notificaciones
- **Permisos:** la reactivación (UPDATE) solo la invocarán servicios con permiso de Administración (RN-003). El repositorio **no** valida permisos; eso es de la BLL (HU-019 y HU-020). No implementarlo aquí.
- **Auditoría:** desactivar y reactivar generarán auditoría cuando exista HU-008. Aquí solo se garantiza el cambio de estado y que `ActualizadoPor` y `FechaActualizacionUtc` se registran.
- **Notificaciones y analítica:** ninguna.
- **Seguridad:** sin secretos en código ni en pruebas (la contraseña del fixture es solo de pruebas y ya existe). El rol `nilogistic_app` sigue sin DELETE.
