## 2. Objetivo
Dos tablas y un servicio de la BLL para tener **evidencia verificable del consentimiento**: (1) `app.documentos_legales`: versiones inmutables de la política de privacidad, los términos y la política de cookies, con **una sola versión vigente por tipo**; (2) `app.aceptaciones_legales`: registro de solo inserción de qué versión aceptó cada persona, cuándo (UTC) y desde qué IP. El servicio publica versiones (cierra la anterior y abre la nueva en una sola transacción), consulta la vigente y el historial, y registra aceptaciones rechazando las de una versión que ya no es la vigente (E4). Cada publicación y cada aceptación se **audita en la misma transacción**. **No hay pantalla, endpoint ni vista** (las páginas públicas son HU-044; el banner, HU-045; los formularios que aceptan, HU-025 y posteriores).

### 4.1 Pase A — Migración SQL (`supabase/migrations/20261109001000_documentos_legales.sql`)
Timestamp mayor que el último (`20261109000900`; D-21). Una sola transacción; **idempotente** (el CI la aplica dos veces); mismo rol dueño que las anteriores (D-081).

1. **`app.documentos_legales`** (`create table if not exists`): `id uuid primary key default gen_random_uuid()`, `tipo text not null check (tipo in ('privacidad','terminos','cookies'))`, `version int not null check (version >= 1)`, `contenido_html text not null check (length(contenido_html) between 1 and 200000)`, `vigente_desde_utc timestamptz not null`, `vigente_hasta_utc timestamptz null`, `publicado_por uuid null` (**sin** clave foránea: todavía no existe `identidad.usuarios`), `creado_utc timestamptz not null default now()`. Restricciones: `unique (tipo, version)` y `check (vigente_hasta_utc is null or vigente_hasta_utc > vigente_desde_utc)`. **Índice único parcial** `ux_documentos_legales_vigente on app.documentos_legales (tipo) where vigente_hasta_utc is null` (E3). Sin columnas `activo`, `actualizado_*` ni `creado_por` (SUP-5: una versión no se edita ni se desactiva).
2. **`app.aceptaciones_legales`** (solo inserción): `id uuid primary key default gen_random_uuid()`, `documento_legal_id uuid not null references app.documentos_legales(id)`, `contexto text not null check (contexto in ('solicitud_alta','newsletter','contacto','perfil'))`, `referencia_id uuid null`, `aceptado_utc timestamptz not null`, `ip inet not null`, `user_agent_hash text null check (user_agent_hash is null or user_agent_hash ~ '^[0-9a-f]{64}$')`. Índice `ix_aceptaciones_legales_contexto_ref on (contexto, referencia_id)` y `ix_aceptaciones_legales_documento on (documento_legal_id)`.
3. **Inmutabilidad (defensa en profundidad, también para el propietario)**, imitando los triggers de `20261109000800_auditoria_inmutable.sql` (mismo `errcode` y estilo de mensaje, sin volcar contenido):
   - `app.proteger_documento_legal()` + trigger `trg_documentos_legales_inmutable` `before update or delete`: el `delete` siempre se rechaza; el `update` solo se admite si **únicamente** cambia `vigente_hasta_utc` **de nulo a un valor** (no se reabre una versión cerrada ni se cambia un cierre). Cualquier cambio de `tipo`, `version`, `contenido_html`, `vigente_desde_utc`, `publicado_por`, `creado_utc` o `id` se rechaza.
   - `app.proteger_aceptacion_legal()` + trigger `trg_aceptaciones_legales_inmutable` `before update or delete`: rechaza siempre.
   Las funciones: `language plpgsql`, `security invoker`, `set search_path = pg_catalog, app`; `create or replace` + `drop trigger if exists` + `create trigger`.
4. **RLS de denegación por defecto** (`enable row level security`) y políticas para `nilogistic_app` **por comando**, cada una precedida de `drop policy if exists`: en `documentos_legales` → `select`, `insert` y `update`; en `aceptaciones_legales` → `select` e `insert`. **Sin política de delete** en ninguna.
5. **Privilegios por columna:** `revoke insert, update, delete on ... from nilogistic_app` en ambas tablas y luego `grant select, insert` en ambas, y `grant update (vigente_hasta_utc) on app.documentos_legales to nilogistic_app`. La aplicación no puede actualizar nada de `aceptaciones_legales`. Sin `delete` (ya ausente).
6. **Comentarios** `comment on table/column` en español (como `20261109000900`), incluyendo que `contenido_html` es inmutable y que la IP se guarda completa como evidencia.
7. **Sin semilla** (SUP-4): los textos provisionales los publica HU-044 (versión provisional, RN-056; definitiva antes de G6).
8. Confirma que `scripts/ci/verificar_rls.sql` sigue en verde y réplica local del job `sql` (migraciones ×2). Si el trigger o los privilegios lo rompen, **no relajes la guardia**: anótalo en «Dudas».

#### 4.3.a Comportamiento de `ServicioDocumentosLegales`
- **Lecturas:** `tipo` que no esté en `TiposDocumentoLegal.Todos` → `ArgumentException` con mensaje genérico (error del llamador, no entrada de usuario). `ObtenerVigenteAsync` devuelve `null` si no hay versión vigente.
- **`PublicarAsync` (E1, E3):** (1) valida `Tipo` y contenido con `ValidadorContenidoLegal` → `Invalido` con su mensaje; (2) lee el historial y calcula `version = (máxima existente) + 1` (1 si no hay ninguna); (3) `VigenteDesdeUtc = reloj.AhoraUtc` (SUP-2: sin versiones programadas); (4) construye el asiento y llama a `PublicarAsync` del repositorio; (5) `Conflicto` si el repositorio lo devuelve (publicación simultánea o versión ya tomada) — **la anterior no queda cerrada ni la nueva abierta**; (6) `Publicado` con el `DocumentoLegalResponse`. No hay forma de publicar una segunda versión vigente sin cerrar la anterior: el cierre y la apertura ocurren en la misma transacción (E3), y el índice único parcial lo garantiza aunque se salte la BLL.
- **`RegistrarAceptacionAsync` (E2, E4):** (1) valida `Tipo`, `Contexto` y `VersionMostrada >= 1` → `Invalido`; (2) exige `IContextoAuditoria.Ip` no nula → `Invalido` («No se pudo determinar el origen de la solicitud.»), porque la columna es obligatoria y la IP es evidencia; (3) lee la vigente: si no hay → `SinVersionVigente`; (4) si `VersionMostrada != vigente.Version` → `VersionObsoleta` con `VersionVigente` (E4: **no** se escribe nada; el formulario deberá mostrar el texto vigente y pedir de nuevo la aceptación); (5) crea la `AceptacionLegal` con `AceptadoUtc = reloj.AhoraUtc`, la IP del contexto y `UserAgentHash` = SHA-256 hexadecimal en minúsculas del `UserAgent` del contexto (nulo si no hay); (6) `Registrada` con la versión aceptada. `ReferenciaId` es opcional.
- **Asientos de auditoría explícitos** (el interceptor no cubre estas entidades), con usuario, rol, IP, user agent y correlación de `IContextoAuditoria`, `OcurrioUtc = reloj.AhoraUtc` y JSON con `System.Text.Json`:
  - Publicación: `Tipo = "gestion"`, `Accion = "version_legal_publicada"`, `Entidad = "app.documentos_legales"`, `EntidadId = <id del documento>`, `Antes = {"version": <anterior|null>}`, `Despues = {"tipo","version","vigente_desde_utc"}`, `Detalle = {"tipo","version","version_anterior"}`. **El contenido no se incluye** en la auditoría.
  - Aceptación: `Tipo = "gestion"` (SUP-6), `Accion = "aceptacion_legal_registrada"`, `Entidad = "app.aceptaciones_legales"`, `EntidadId = <id de la aceptación>`, `Despues = {"documento_legal_id","tipo","version","contexto","referencia_id"}`.
- **Sin autorización, sin 2FA, sin correo** (SUP-3): el permiso «Administrador (READ, CREATE, UPDATE)» se aplica cuando exista la superficie HTTP (HU-019/HU-020 y la pantalla de textos legales). El servicio **no tiene superficie HTTP** en esta HU.
